What changed, and why

Problem todayIn this proposal
Four stacked SettingsExpanders, each hiding a sub-card that repeats the same “Storage and synchronization” header and the same two radio buttons. ~700 px tall, scrolls. One decision per capability. The on/off toggle and the source radios collapse into a single 2–3 segment control: Off · Sync · This PC. No expanders, nothing hidden, ~330 px tall.
“Provider contacts” vs “Local contacts” states where but never what it costs you. A live consequence line under each capability restates the choice in outcome terms (“syncs to every device” vs “stays on this PC, no backup”), and cloud/device icons carry the same meaning in the segments.
Reads as a generic settings list; the OAuth consent screen that follows is a surprise. Capability tiles with iconography and an accent-tinted “on” state, plus a permission summary that names exactly which scopes the provider will be asked for — the consent dialog stops being a surprise.
Provider-specific rules (IMAP has no provider tasks; CardDAV behind a flag) surface as extra InfoBar cards inside expanders. Unavailable segments are simply disabled with the reason inline, so the tile count and layout never change between providers.

WinUI mapping (nothing here needs a custom control)

  • Tile / row → Border in an ItemsRepeater with UniformGridLayout (A) or StackLayout (B). Option B is also a straight SettingsCard stack if you prefer zero custom templating.
  • Segmented mode picker → CommunityToolkit.WinUI.Controls.Segmented with SegmentedItem (Icon + Content); IsEnabled=false per item for unavailable sources.
  • Consequence line → TextBlock bound to a computed VM property per capability.
  • Mail range → the existing ComboBox, moved inline into the Mail tile; the “Everything” warning stays a muxc:InfoBar.
  • Permission summary → ItemsControl of pill Borders over a computed scope list.

View-model impact

  • Each capability’s Is…AccessEnabled + Selected…SourceIndex pair collapses into one enum property (Off / Provider / Local). The existing bools become computed passthroughs, so WelcomeWizardContext and the tests keep working.
  • The four Is…ExpanderExpanded properties are deleted outright — nothing expands any more.
  • Three new computed strings per capability (state summary, consequence text) plus one scope list for the summary block.
